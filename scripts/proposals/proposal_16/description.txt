Adopt the Olas protocol instance on Robinhood Chain as canonical. A complete deployment of the Olas protocol now exists on Robinhood Chain (chain Id 4663): the service and agent registries, service management, the staking factory and verifier, the mech marketplace, and the buy-back stack are all live, their source is verified, and every contract that has an owner is already owned by this DAO through the chain's governance control point. What that deployment is not yet is part of the protocol. The protocol's L1 contracts do not recognise the chain, so no staking incentives can reach it and the community multisig cannot act on it. This proposal asks the DAO to recognise that deployment as the canonical Olas instance on Robinhood Chain, and to connect it to the protocol on L1 accordingly. It (1) registers the Robinhood Chain deposit processor with the Dispenser, so that staking incentives can be claimed for nominees on that chain; (2) registers the Robinhood Chain bridge route in the GuardCM community multisig guard by calling setBridgeMediatorL1BridgeParams, so that community multisig transactions to Robinhood Chain are verified the same way as those to Arbitrum One, which uses the same Orbit bridge-data verifier; and (3) allowlists in GuardCM exactly the selector set the community multisig already holds on the other chains: the pause selector for the Robinhood Chain service manager proxy and target dispenser, and the drain selectors for the Robinhood Chain service registry and service registry token utility. The unpause selector is deliberately excluded, because it is allowlisted on no other chain. Entries (2) and (3) are submitted together deliberately: an allowlist without bridge parameters leaves community multisig transactions failing closed, as was the case for Mode until proposal 13.
